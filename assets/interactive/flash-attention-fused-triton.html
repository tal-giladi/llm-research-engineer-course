What “fused” means here

All the highlighted work—loads, QKᵀ, online softmax, weighted V accumulation, and final stores—is compiled into one forward kernel. Its launch creates a grid of programs. Program 0 owns Q1–Q2 and O1–O2; program 1 owns Q3–Q4 and O3–O4. Each loops over both K/V tiles independently.

One kernel is not one GPU thread, one program, or one giant register. In a conventional NVIDIA lowering, a program corresponds to a thread block with several warps; a warp contains 32 threads. Tensor tiles are distributed among their threads. Register and shared-memory capacity constrain tile size, not total sequence length.

The diagram uses shared memory as a conceptual operand-staging route. Actual placement depends on the Triton version, architecture and generated instructions. Registers hold scalar/reduction state and accumulator fragments in conventional kernels; some newer implementations also use specialized tensor memory. There is no guaranteed one-to-one mapping between a Python variable and a physical storage box.

Why the numbers change when Triton uses exp2

The earlier animation used natural exponentials: S = QKᵀ / √d and exp(S − m). Here we use Z = S × log₂(e), so 2^(Z − m₂) is the same weight as exp(S − m). The running maximum m₂ is measured in base-2 units, while ℓ and A retain the same mathematical values.

2^(x × log₂(e)) = exp(x)
Z = (QKᵀ / √d) × log₂(e)
m₂ = maximum Z seen so far
α = 2^(m₂_old − m₂_new)
W = 2^(Z − m₂_new)
ℓ_new = α × ℓ_old + row_sum(W)
A_new = α × A_old + W @ V
O = A / ℓ
L₂ = m₂ + log₂(ℓ)       # saved base-2 log-sum-exp
L_natural = L₂ × ln(2)

When reconstructing probabilities, use P = 2^(Z − L₂). Do not combine a base-2 L₂ with natural exp. The reference panel verifies the conversion against the first animation.

Scope, real Triton code, and embedding

The animation uses JavaScript doubles to keep the mathematics clear. Real kernels commonly use lower-precision operands with FP32 accumulation; converting W to the dot-product input dtype introduces rounding. We show that conversion explicitly but do not simulate its rounding. No performance claims or measured memory counts are implied.

Two-by-two tiles are for readability, not valid efficient Triton dot configurations. Production kernels need appropriate block sizes, layouts, boundary masks, numerical tests, dtype handling and architecture-specific tuning. We omit pipelined prefetch and warp specialization so each dependency stays visible; real kernels can overlap memory work and computation.

For runnable GPU code, use the maintained official Triton fused-attention tutorial. This explainer follows its FA2-style online accumulation and base-2 exponential convention, with a simplified operation order.
