What this example simplifies
  • The clock starts at backward. Forward A → B → C and loss calculation have already finished on each GPU. Backward computes gradients in C → B → A order.
  • One bucket per layer is a teaching simplification. A real bucket can contain multiple parameter tensors and can cross layer boundaries. All gradients in a bucket must be ready locally; ranks must issue collectives in matching order, and completion depends on all participating ranks.
  • Both ranks have equal timing here. Each layer's backward takes 4 ms; each collective takes 3 ms. We assume no compute/communication slowdown from resource contention. These are illustrative values, not benchmark results.
  • Numbers in the tiles are invented two-element gradient vectors, not weights or activations. For this ordinary, equal-weight two-rank example, each completed bucket contains the mean of the ranks' local gradients.
  • The after-backward schedule is a comparison, not a PyTorch DDP mode. Ordinary DDP starts reduction during backward; by the time loss.backward() returns, its gradient synchronization has completed. The optimizer step then runs independently on each rank using synchronized gradients.
  • No optimizer step is simulated. Matching starting weights, optimizer states and updates keep replicas aligned. DDP does not split the input data for you.
