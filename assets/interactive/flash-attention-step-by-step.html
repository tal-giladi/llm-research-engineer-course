What exactly is kept between K/V tiles?

Independently for each query row: m, the maximum score seen; ℓ, the sum of exp(score − m); and A, the vector sum of exp(score − m) × V. A is a numerator, not yet the final output.

When a later tile raises m, multiply both old ℓ and old A by α = exp(mold − mnew). This changes their scale without revisiting old scores. At the end, O = A / ℓ. The intermediate normalized softmax probabilities are never needed as a full matrix.

L = m + ln(ℓ) is one saved log-sum-exp per query for the backward pass. This demo writes L alongside O. During backward, probabilities can be reconstructed from recomputed scores and L; that pass is outside this animation.

Reference only: full scores, final probabilities, and a numerical check

This panel is a teaching reference computed separately. These full matrices are not buffers kept by the animated FlashAttention kernel. A full probability row sums to 1; a temporary W row usually does not.

Algorithm, scope, and embedding this animation
for each Q tile:                         # 2 query rows here
    load Q_tile
    m = −∞; ℓ = 0; A = 0                 # per query row
    for each K/V tile:                   # 2 key/value rows here
        load K_tile, V_tile
        S = Q_tile @ K_tile.T / sqrt(d)
        m_new = max(m, rowmax(S))
        α = exp(m − m_new)
        W = exp(S − m_new[:, None])
        ℓ = α * ℓ + rowsum(W)
        A = α[:, None] * A + W @ V_tile
        m = m_new
    O_tile = A / ℓ[:, None]
    L_tile = m + log(ℓ)
    write O_tile, L_tile

This is a pedagogical FlashAttention-2-style forward schedule with no mask and no dropout. In GPT causal attention, future-key scores are masked to −∞ before the maximum and exponentials; their exponential weights are zero. The animation serializes arithmetic and query tiles for learning. Real kernels parallelize query tiles, use Tensor Cores, and can overlap loads and computation. On-chip placement, buffer reuse, caches, and precision vary by kernel; separate S/W boxes here show logical values, not necessarily distinct physical buffers.

The counts are logical scalar transfers for this tiled schedule, not measured HBM transactions. Tiny matrices illustrate the method, not a speed benchmark. The arithmetic is JavaScript floating point, not a GPU execution or a simulator of BF16 rounding.
