### C-20261030-01 · TRL ships "Keep Sampling Mask" unbiased importance sampling + default score-centering (DeepSeek-V3.2 mismatch fix becomes standard in a major RL-training stack)

- **Class:** A
- **Date discovered:** 2026-10-30
- **Date published:** 2026-10-29 (TRL v1.17.0 release)
- **Source:** https://github.com/huggingface/trl/releases/tag/v1.17.0 (verified resolves; GitHub release, 29 Oct 2026)
- **Organization/researchers:** Hugging Face (TRL maintainers, trainer-side implementation + default); DeepSeek-AI (originating technique — DeepSeek-V3.2 technical report, arXiv:2512.02556, "Section 3.3" per vLLM's own docs; the arXiv page itself was verified to resolve and to be the real DeepSeek-V3.2 report, title and ~264 DeepSeek-AI authors confirmed, submitted 2025-12-02 — the section-3.3 attribution is per vLLM's documentation, not independently re-read from the PDF body in this check); vLLM project (inference-engine-side implementation, `docs.vllm.ai/en/stable/training/sampling_mask/`).
- **Category:** RL/post-training (training-inference mismatch correction; directly extends the accepted topic behind lesson 16.4)
- **What changed:** Rollouts sampled with top-k/top-p/min-p truncation and training that scores log-probabilities over the full vocabulary normalize over *different token sets* ("action spaces"), biasing the GRPO/PPO importance-sampling ratio toward 0 — a mismatch source that cannot be fixed by reweighting (a token the engine could never sample has probability exactly 0 under it, so no importance weight can reintroduce its contribution). The DeepSeek-V3.2 technical report's "Keep Sampling Mask" strategy fixes this by recording the exact surviving token IDs at each rollout step and renormalizing *only over that surviving set* on the training side, so both policies normalize over identical support. vLLM implements the engine side of this (`--return-sampling-mask`, `--logprobs-mode processed_logprobs`, requires `top_k > 0`, Model Runner V2). TRL v1.17.0 (29 Oct 2026) now implements the trainer side: it normalizes over each token's candidate set following this approach, and — separately but in the same release — makes "score centering" with masked importance sampling (`importance_sampling_min=0.5`, `max=5.0`) the new *default* AsyncGRPO objective in place of the old clipped objective.
- **Technical summary:** TRL's own release notes report that with the old clipped objective, an FP8 rollout sampler collapses GRPO training to a reward of 0.34 or 0.10, whereas enabling score-centering with masked IS trains the FP8 sampler like a BF16 one (~0.72 reward) — at a reported 15-20% generation-throughput cost. The mask-based importance-sampling fix is a separate, also-new-in-this-release breaking change (GRPOConfig now errors if `top_p<1.0` or `min_p>0` is set without `top_k>0` under the default vLLM-IS-correction path), i.e. TRL requires users to supply a bounded candidate set so the mask can be applied.
- **Why it might matter:** The course's lesson 16.4 (`lessons/module-16/lesson-04.md`, ADD 2026-10-25) already identifies this exact mismatch source in prose — "If the engine can never produce an action ($\mu(a)=0$...), no weight can bring its term back... score the tokens under the same truncated distribution in the trainer, or sample without truncation during RL" — but cites no concrete production implementation of that fix, and `code/src/llmre/rl/mismatch.py`/`research/accepted/rl-training-inference-mismatch.md`'s evidence list only covers the *other* mismatch causes (kernel/reduction-order, batch composition, precision, MoE routing) via vLLM batch-invariance, verl rollout-correction and TorchTitan. This find supplies the missing concrete citation and production implementation for a mechanism the lesson already teaches conceptually but cannot yet point to in a shipped system.
- **Evidence of adoption:** Two major, independently maintained open-source stacks now implement it: vLLM (inference-engine feature, documented, requires Model Runner V2) and TRL (trainer-side default as of v1.17.0, 29 Oct 2026) — this is adoption in widely-used OSS training/serving infrastructure, not a single paper's self-report. The underlying technique is DeepSeek's own reported practice for DeepSeek-V3.2's RL training (**company claim** for DeepSeek's own results; the OSS-adoption evidence is independent of that claim).
- **Major organizations using it:** DeepSeek (originator, DeepSeek-V3.2); Hugging Face (TRL, now default for AsyncGRPO users); vLLM project.
- **Open-source implementation:** https://github.com/huggingface/trl (v1.17.0+); https://docs.vllm.ai/en/stable/training/sampling_mask/ (vLLM, feature flag `--return-sampling-mask`)
- **Paper:** https://arxiv.org/abs/2512.02556 (DeepSeek-V3.2 technical report, §3.3 per vLLM's docs)
- **Code:** https://github.com/huggingface/trl/releases/tag/v1.17.0
- **Relationship to existing course material:** Direct, concrete extension of the **ACCEPTED** topic `research/accepted/rl-training-inference-mismatch.md` (lesson 16.4, ADD 2026-10-25). Checked via `lookup "importance sampling top-k top-p vLLM mismatch"` and `lookup "truncated importance sampling RL training inference mismatch"` (both hit the existing accepted file/lesson/code, confirming this is the same topic, not a duplicate needing no record) and `lookup "Keep Sampling Mask DeepSeek"` and `lookup "score centering AsyncGRPO"` (no hits — this specific named technique and its new OSS implementations are not yet in the registry, so it is genuinely new evidence, per the daily protocol's rule for new evidence on existing material). Grepped `lessons/module-16/lesson-04.md` and `code/src/llmre/rl/mismatch.py` directly: the lesson already states the correct fix in prose (section 5.3 and the "Ignoring sampling transforms" common-mistake) but names no production system; the evidence list in the accepted topic file and the code module's docstring do not mention Keep Sampling Mask, DeepSeek-V3.2, or this TRL release.
- **Potential course lesson:** Not a new lesson — a worked addition to 16.4 and the accepted topic's evidence list: name the mechanism ("Keep Sampling Mask"), cite DeepSeek-V3.2 §3.3 and the vLLM/TRL implementations, and optionally extend `code/src/llmre/rl/mismatch.py` with a small toy function showing renormalization restricted to a top-k candidate set (mechanically what section 5.3 already describes without code).
- **Confidence:** high — two independently maintained major OSS stacks now ship this as a documented, citable feature, with TRL's own benchmark numbers showing a concrete training-collapse-vs-stable contrast (0.72 vs. 0.34/0.10 reward); the only soft spot is not having independently re-read the DeepSeek-V3.2 PDF's §3.3 text directly (the section attribution rests on vLLM's own documentation, which is itself an official primary source, not a secondary blog).
- **Recommendation:** strong candidate for the weekly review as a worked addition to the already-accepted 16.4/`rl-training-inference-mismatch` material (new citations + evidence-list entries + one small code example), rather than a new lesson, since the concept is already taught — likely low-risk, cheap to spot-check against the existing toy harness in `code/src/llmre/rl/mismatch.py`.

### C-20261030-02 · WorkFactory: scalable synthetic professional-task generation for agent training

- **Class:** B
- **Date discovered:** 2026-10-30
- **Date published:** 2026-10-27 (v1)
- **Source:** https://arxiv.org/abs/2610.37161 (verified resolves; v1, Tue 27 Oct 2026 12:54:16 UTC; discovered via Hugging Face's Oct 30 daily-papers curation — not yet in arXiv's announced daily listing as of this run, see coverage note above)
- **Organization/researchers:** Ziyang Zeng, Tingyang Chen, Jia Deng, Qiyao Wang, Shuo Tang, Yike Yang, Tao Ren, Wayne Xin Zhao, Feng Chang, Jujie He, Chuan Hao, Ran Tao, Bryan Dai (13 authors; affiliations not stated on the abstract page; code hosted under GitHub org "IQuestLab").
- **Category:** agents/tool use + data curation (scalable synthetic task/environment generation for agent training)
- **What changed:** Argues that training capable "work agents" needs diverse professional tasks with reliable expert demonstrations, and that missing/inconsistent task information undermines those demonstrations. WorkFactory starts from professional intents, builds an information-level "support graph" mapping what information an intended output needs and where it lives, then uses probe executions to detect support failures and drive repairs without changing the intended task. The authors built 112,686 tasks across 612 occupations this way and fine-tuned Qwen at 4B/27B/35B-A3B scale on teacher trajectories (the "WorkPilot" family).
- **Technical summary:** Authors' own results: all three WorkPilot sizes outperform their base models on four professional-work benchmarks; WorkPilot-35B-A3B improves from 879 to 1565 Elo on GDPval-AA v2.1. Scaling shows model-dependent diminishing returns. Ablations show the planning+repair steps reduce probe-diagnosed task-environment defects and improve downstream performance. Data and models released on GitHub (linked from the abstract page; exact URL not independently re-verified beyond the abstract page's claim).
- **Why it might matter:** A concrete, large-scale ("112,686 tasks / 612 occupations") instance of synthetic, verification-driven task generation for agent SFT — relevant if the course's agents/tool-use module ever teaches how large-scale agent training data/environments get built rather than only how agents are trained once data exists.
- **Evidence of adoption:** None beyond the authors' own release — single paper, three days old at discovery, no third-party reproduction or use found.
- **Major organizations using it:** None identified; academic authorship, no stated lab affiliation.
- **Open-source implementation:** GitHub (IQuestLab org, per the abstract page; URL not independently re-verified beyond the abstract's own link).
- **Paper:** https://arxiv.org/abs/2610.37161
- **Code:** per abstract page, GitHub (IQuestLab org) — not independently re-verified

### C-20261030-03 · WebAnything: automated reconstruction of web environments for agent training

- **Class:** B
- **Date discovered:** 2026-10-30
- **Date published:** 2026-10-27 (v1)
- **Source:** https://arxiv.org/abs/2610.37786 (verified resolves; v1, Tue 27 Oct 2026 18:06:58 UTC; discovered via Hugging Face's Oct 30 daily-papers curation — not yet in arXiv's announced daily listing as of this run, see coverage note above)
- **Organization/researchers:** Tianci Xie, Zikun Cai, Chaoyun Zhang, Pinxue Guo, Bingxuan Li, Rui Zheng, Hang Yan (7 authors; affiliations not stated on the abstract page).
- **Category:** agents/tool use + data curation (automated web-environment reconstruction for agent training/evaluation)
- **What changed:** Argues existing ways of building web-agent training/eval environments fall short: human-assisted mirrors need per-site engineering, generated sites can drift from the real ones, and capture-and-replay limits interaction to what was recorded. WebAnything's "Explorer-Builder" automatically collects browser-visible structure, resources and interaction outcomes from a live URL (with only initial setup/authorization, not per-site manual work) to rebuild a reusable, source-grounded environment; a separate verifier checks frozen candidates and triggers local repairs or targeted recapture.
- **Technical summary:** Authors' own results: built 244 website artifacts across 14 domains/53 categories, supporting 12,984 executed and accepted tasks. In a blind audit against the human-assisted "WebHarbor" baseline, scored higher on three fidelity metrics (12 wins, 2 ties, 0 losses). Fine-tuning Qwen3.5-9B on 5,856 collected interaction trajectories improved REAL success by 9.9pp, Odysseys-Easy Rubric/Task averages by 6.25/6.32 points, and WebArena-Verified overall success by 13.33pp under a fixed harness. Code released on GitHub (per abstract page).
- **Why it might matter:** Same underlying pattern as WorkFactory above but for web agents specifically: automated, verified environment generation at scale, with a reported downstream training benefit on standard web-agent benchmarks (WebArena-Verified, REAL) — relevant to the agents module if it ever covers how web-agent training/eval environments are built rather than only the agent policies trained on them.
- **Evidence of adoption:** None beyond the authors' own release — single paper, three days old at discovery, no third-party reproduction or use found.
- **Major organizations using it:** None identified; academic authorship, no stated lab affiliation.
- **Open-source implementation:** GitHub (per abstract page; URL not independently re-verified beyond the abstract's own link).
- **Paper:** https://arxiv.org/abs/2610.37786

- **Confidence:** low-medium — real engineering scale (244 sites, 12,984 tasks) and a concrete downstream fine-tuning benefit on standard benchmarks, but single paper, no independent reproduction, no stated venue.
